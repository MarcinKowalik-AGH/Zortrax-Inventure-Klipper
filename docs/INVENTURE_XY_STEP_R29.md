# Inventure R29 RC1 | STEP 2.45 µs

R29 uses the high time of the working M300 Classic port, rounded to the
Inventure timer resolution. In M300, the configured 2 µs pulse is 144 DWT
ticks. The finite STEP driver adds 32 ticks at 72 MHz, giving 2.444… µs.
R29 uses 147 ticks at the 60 MHz timer clock, or **2.45 µs**, on both
fast native XY STEP outputs.

| Operation | PA7 | PA6 |
| --- | --- | --- |
| Finite constant-period blocks | TIM3 PWM with the TIM2 falling-edge gate, as in M300 | TIM6 and DMA1 stream 1 start TIM13 hardware one-shots |
| Changing intervals and short blocks | TIM14 hardware one-shot | TIM13 hardware one-shot |
| Accepted slow Home and trigger-armed blocks | Existing Klipper GPIO pulse | Existing Klipper GPIO pulse |

TIM13/14 are the r0323 STEP outputs and are also used by the existing
SERVICE engine. They are returned to their idle register state after
native motion drains. The native step queue remains busy until the
last pulse and its low interval finish. OLED stays on SPI2 and DMA1
stream 4. Each PA6 high pulse is generated by TIM13 itself. DMA
latency affects its launch time while the high time is determined by
the timer. Startup tests keep the STEP outputs disconnected from test
signals and verify the timer gates with drive enable off.

## r0323 motion limits

The project archive's original r0323 image starts at `0x08010000`
and has SHA-256
`9b980ba04531fac4425b77a23969076d24d8f25629fc2a501ac05d262c142268`.

| Evidence | Interpretation in the CoreXY branch |
| --- | --- |
| `0x08036D3C` | 640 STEP/mm on both XY motors |
| `0x0801F4D4–0x0801F4F4` and `0x0801F5F2–0x0801F656` | The planner applies the `200, 200, 20` table at `0x08036D4C` after forming the A/B displacements from X/Y |
| `0x08024336–0x08024340`, `0x080381B4`, `0x0801FAC2–0x0801FAE2` | Startup copies 1500.0 to `0x20000BD4`. The mixed-motion planner reads it for acceleration |
| `0x08013E00` and TIM6 setup at `0x08013E28` | The shortest programmed period has ARR 10 and a 2 MHz timer tick rate, giving 5.5 µs |

At 640 STEP/mm, the stock motor feed cap is 128,000 STEP/s. It
allows **200 mm/s along X or Y** and **141.42 mm/s on a 45° diagonal**.
The faster 5.5 µs timing bound corresponds to about 181,818 STEP/s
per motor. It provides room for the firmware pulses and scheduling
while the R29 host applies the OEM motor feed and mixed acceleration
limits. The field setup's `microsteps`, `rotation_distance`,
`step_pulse_duration` and default velocity/acceleration remain the
existing configuration. The fast timer produces 2.45 µs independently
of the 4 µs software pulse used by that configuration for Home.

## Install the paired host and MCU

1. With InventureBoot 1.7, load `INVENTUR.IVB` from the test archive
   through the existing FAT32 SD update procedure. The R29 RC1
   `INVENTUR.IVB` file has SHA-256
   `b6978d31bb5430fb13fb11ae3bb7f425131428164c28859433796d8f4756ce78`.
2. At idle with heater targets off, issue `FIRMWARE_RESTART` and wait
   for Ready. Install before commanding Home or heat.

   ```bash
   cd ~/inventure-src &&
   git fetch origin codex/inventure-native-xy-r29 &&
   git switch --detach FETCH_HEAD &&
   python3 install-new-host.py --repair-home-procedures --with-xy-step-timers \
     --serial /dev/ttyS5 --baud 750000 --apply
   ```

3. Read `INVENTURE_VERSION`, `INVENTURE_XY_STEP_STATUS` and
   `INVENTURE_TRANSPORT_STATUS`. Expect
   `RC8-CONTROL-R7-HOME-R29-XY-OEM` and `verified=3 enabled=1 active=0`.
   Run Home XYZ from OLED and Fluidd with the existing settings. A fast
   move then increases the appropriate `steps_a/steps_b` counters.
   `blocks_a/blocks_b` count the completed constant-period blocks.
4. With the machine homed and the carriage at its safe clearance,
   the OEM planning envelope can be selected for a separate test by
   `SET_VELOCITY_LIMIT VELOCITY=200 ACCEL=1500`. The configured
   limits are read again on Klipper restart. The host keeps the paired
   low-speed limit if the MCU reports a startup test failure.

For rollback, use the previous application image and the same host
installer. With `--with-xy-step-timers` the installer reads the MCU
version and pairs the corresponding R28 or R29 host. The existing
Home repair mode is also available without the STEP flag.

## Validation

Build `ci/build_inventure_xy_step_r29.py` with the pinned kit and GNU
Arm 14.2.1. The two compiled IVB files are byte-identical.
`ci/check_inventure_xy_step_arm_r29.py` executes the linked ARM firmware
against a timer/DMA model. Both outputs hold high for 294 DWT ticks
through constant blocks, short blocks and changing periods. Its cases
include 128 kHz per motor, a 5.5 µs train, asynchronous starts, a wrap
of the DWT clock, modeled sampler stalls and motor-enable aborts.

`ci/check_inventure_home_r24.py --transport-r26 --xy-step-timers r29`
stages the R29 runtime and validates the OEM limits through Klipper's
CoreXY move checker. The accepted Home entry points, refusal paths,
and OLED/Fluidd routing run against the same staged configuration.
The linked UART replay handles all 312 arrival scenarios. The
modeled pulse widths and replay results await physical acceptance on
the Inventure.
