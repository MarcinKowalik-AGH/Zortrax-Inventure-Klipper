# Inventure R38 operator procedure audit

Host `RC8-CONTROL-R7-HOMING-R38` runs with MCU `RC8-CONTROL-R7-DISPLAY-R14`. R38 updates the Orange Pi. The evidence covers the field configuration, a fresh installation and the existing R14 hardware interface. A physical acceptance run of R38 is outstanding.

## Why the Home All button stopped

The two console messages at 20:54 reproduce in R37. The Fluidd Tool card sent the correct public command, `INVENTURE_HOME_ALL`. Its macro forwarded an unacknowledged request to a bench command. Starting in OFF failed the native ownership check. After the operator selected NATIVE, the MCU reported armed, with fault and latch zero. The second request then failed before the first move because the electrical Z reference requires a reviewed pad and clear travel. The earlier tests exercised the web command and an explicitly acknowledged sequence separately. Neither test executed the installed macro as the operator clicked it.

R38 sends all five public homing macros through the operator entry. Home All and Home Z open **Pad and clearance OK?** in Fluidd and on the physical OLED. Confirm **Yes / Start** after checking that T0 is physically lowered, the tray is seated, the calibrated center pad is clear and the platform has free travel. The review displays the configured or requested nozzle temperature. Back, expiry, a stale choice and a control STOP cancel authority to start. Home X, Y and XY from the Tool card start the cold clearance sequence directly. Home Z needs referenced XY. Home All handles both XY references, in Y then X order. On the Z path, the sequence seeks the bottom reference, positions over the configured pad, heats T0, verifies contact/release and parks at the configured clearance. The individual axes, pad geometry, speeds and accepted offsets come from the Inventure configuration.

The host asks the MCU for NATIVE once when an idle OFF or SERVICE controller is eligible. It verifies the reply and continues to check ownership through motion. Only the confirmed menu action supplies the electrical-reference acknowledgement. Scripts which already verify the physical prerequisites can still use `INVENTURE_HOME_ALL ACK=PAD_AND_CLEARANCE_CHECKED`. The raw bench commands retain their explicit contracts.

## Verification scope

The release test loads the field upgrade and a fresh include tree using the project's pinned Klipper. It renders **89** and **109** public macro definitions respectively with an idle state and representative procedure state/arguments. It resolves emitted command names against the Klipper registry and executes literal Home button commands through the G-code parser. Differences in the two counts come from the diagnostic macros included by the two configurations. The static operator and bench menu inventory covers **41 pages and 97 distinct actions**. Dynamic menu choices and physical motion have separate tests. The host suite exercises motion and service owners using simulated inputs and MCU responses. Eight compiled C register-test programs exercise the MCU code. Chrome, Klipper and Moonraker integration checks run in CI.

All 809 host regression tests passed. In a separate upgrade test, the R37 installer first produced the organized field configuration. Upgrading its 12 active configuration files to R38 changed only `inventure_operations.cfg`. All five homing macros acquired the new entry, the customized OLED brightness survived and running the update again produced an empty change set. Four independent PID settings also survived Klipper's save and reload in both startup fixtures.

The October stock firmware review, the 24-package matrix with 85 individual requirements, the R23 acceptance log and the five-point result are the reference for machine claims. Open OEM items include reader and tag writeback, reading model files from the physical printer SD, importing and resuming stock saved jobs, persistent print checkpoints, tool-PCB temperature qualification and the complete native dual-material print cycle. The field evidence for homing and calibration does not qualify those functions. ## Install and operate

Run on the Orange Pi while the printer is idle.

```bash
git -C "$HOME/inventure-orange-pi" fetch origin tag inventure-homing-r38 &&
git -C "$HOME/inventure-orange-pi" worktree add --detach "$HOME/inventure-homing-r38" refs/tags/inventure-homing-r38 &&
python3 "$HOME/inventure-homing-r38/install-orange-pi.py" --configure-fluidd --organize-config
```

If the worktree already exists at the release tag, rerun its installer. In Fluidd use `INVENTURE_VERSION` to check the host and MCU revisions. Select **Tool → All**, then **Yes / Start** once the physical checks in the prompt are satisfied. At completion the console or menu reports the homed axes. A site-customized macro retains its own body on upgrade. The installer updates exact published definitions and preserves tuned values and stored calibration results.
